## 이 프로젝트가 실제로 밟은 함정

### 표본은 날짜가 아니라 거래 수로도 봐야 한다

`small_sample` 을 *거래일 수*로만 판정하니, equity 이력이 60일 넘고 **왕복은 2건**인
계좌에서 경고가 안 떴다. 안 고쳤으면 *"2건으로 승률 100%"* 를 경고 없이 보여줬을 것이다.
M3 에서 `rt_count` 조건을 더했다.

### 설정 경로가 둘로 갈리면 셸이 그것을 가린다

launchd 로 첫 실행하니 폰에 `⚠️ 수집 실패: 'ALPACA_API_KEY'` 가 왔다. `config.py`
(pydantic-settings)는 `.env` **파일**을 읽는데 어댑터는 `os.environ` 을 읽고 있었다.
**손으로 테스트할 땐 셸에 이미 export 돼 있어 드러나지 않았다.** `env -i` 로 재현했다.

⇒ 어댑터는 환경변수 *이름* 이 아니라 **값**을 받는다. 셸 export 가 필요 없어진다.

### 3단 견고성은 작동했는데 종료 코드가 거짓말을 했다

두 소스가 다 실패했는데도 리포트는 정직하게 "실패"를 표시하고 발송됐다 — 여기까지는 설계대로다.
**그런데 종료 코드가 0이라 스크립트는 "전송 완료"로 기록했다.** 빈 리포트가 매주 가도
아무도 모를 뻔했다.

⇒ **전 소스 실패면 종료 코드 1.** 부분 실패는 0 — 리포트가 여전히 쓸모 있기 때문이다.

### 잘린 숫자는 누락이 아니라 날조다

딜리버러블이 500자에서 조용히 잘려 `현금 $922,010` 이 `현금 $922,0` 이 됐다.
금융 리포트에서 이건 빠진 게 아니라 **틀린 값**이다. 캡을 올리고 절단 시 고지하게 했다.

### revert 가 중간 개선까지 삼켰다

구분선 폭을 40 → 56 으로 올린 뒤, 별건 실증용으로 28 로 바꿨다가 되돌렸다. 그 revert 가
*"28 실험만"* 이 아니라 **그 이전 커밋 상태로 통째 복귀**해서 56 개선까지 같이 날아갔다.
테스트는 56 을 단언한 채 남아 구현(40)과 어긋났다.

**CI 가 결제 문제로 멈춰 있어서 한 달 넘게 아무도 못 봤다.** 게이트가 안 도는 동안에는
red 가 red 로 보이지 않는다.

⇒ 실험을 되돌릴 땐 **바꾼 줄만** 역치환해라. `git revert`/`checkout <상태>` 는
그 사이의 무관한 개선을 조용히 삼킨다.

### 스케줄의 시간대는 실행기마다 다르다

- **launchd** `StartCalendarInterval` = **로컬 시간**
- **cron** (BSVibe 스케줄) = **UTC**

같은 "월 09:30 KST" 가 전자는 `Hour 9`, 후자는 `30 0 * * 1` 이다. 섞어 읽으면 9시간 어긋난다.

### 로컬 LLM 은 모델 선택이 런타임에 막힌다

해설용 로컬 모델은 설치된 Ollama 가 그 아키텍처를 지원해야 한다 — 최신 모델명을 적어두고
런타임에 로드 실패하면 해설이 통째로 빠진다. 실패 시 **규칙 기반 폴백**으로 떨어뜨렸다.

## 설계에서 안 바꾼 것

**숫자는 결정적 도구가 만들고, 해설만 LLM 이 쓴다.** `--emit` 이 낸 블록을 해설 단계가
**그대로 복사**하고 아래에 덧붙인다(`verbatim` 마커). 숫자가 해설 과정에서 드리프트하는 것을
구조적으로 막는다. 금융 리포트에서 이게 가장 중요한 불변식이다.

## 운영

- Mode A: `bstockreport run --push` + launchd (설치는 `deploy/launchd/*.template` 주석 참조)
- Mode B: 스케줄 실행 → 승인 큐 → 텔레그램 전달
